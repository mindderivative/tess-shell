Reproduced on a private sway with `tests/kwin/probe_hide.py --auto --only=<method>` (toggles run from another window's timer, as a click on the Bar does): a child node's fill changed gets **no frame in 500 ms, four toggles out of four** (`alpha`); the same change followed by `handle.call_soon(noop)` is drawn in 1 to 2 ms (`alphawake`); made inside a `call_soon` callback, 1 to 2 ms (`alphasoon`); the root's `visible` is drawn in 1 to 2 ms alone but 200 to 300 ms late when other windows are being toggled (it waits for a wake that something else causes). So the finding is general: **tre 0.6.1 does not request a frame for a window whose node is changed during a callback of another window**; the change is drawn at the next wake. A hidden Panel that is shown from a click on the Bar is that case, and so are a theme change that touches every window and a module value that feeds a Panel.

The shell now wakes the loop after it changes its windows (`SurfaceManager.wake`, commit 88e4785). **Whether this is the whole fault on KWin is not proven**: please run `/tmp/tess-kwin-m3b/run-keep.sh` again (the traced log will show `a frame 1 ms after it was shown` if it is) and `/tmp/tess-kwin-m3b/probe-hide.sh`, which tries six methods side by side on KWin.

Draft `TRE-REQ` for the maintainer to carry if tre agrees it is tre's (not filed; not mine to file): *A node property change in window B made during a callback of window A (a timer, a listener) is not drawn until another wake. Setting any property from a callback of another window should request B's frame, as it does for the window whose callback it is. Repro: two `LayerWindow`s on sway, `a.after(1000, lambda: b_card.set(fill=...))`, then read B's `frame_stats()["frames"]` or grim: no frame; with `handle.call_soon(lambda: None)` after the `set`, a frame within 2 ms.* The shell's workaround is the wake.

## Differences from the Specs

- [Style Schema](../41%20TDL%20Reference/Style%20Schema.md): `Reach` under `Elevation` is read as a token and not used; the margin comes from each shadow's own numbers (D35). `Shadow_Bleed` is read as `AUTO`, a number, or four sides (a list or named sides) and only on a Bar's `Style`; on any other block it is an unknown key.
- [Style Schema](../41%20TDL%20Reference/Style%20Schema.md): a stylesheet rule's keys are checked against the type it names (an error), and a `.class` or `#name` rule applies only the keys the target takes. State and part selectors are skipped (A2).
- [Portals](../40%20Specifications/Integration/Portals.md): the service thread starts before the surfaces are planned (the first answer waits at most 200 ms, then the defaults); a module does not get the tokens or a `reduced_motion` flag yet.
- [Bar](../40%20Specifications/Surfaces/Bar.md): with a shadow a Bar is a larger surface; the rule is in D37.

## Facts About tre, TEL and tess_dl

- tre 0.6.1: `Window.simulate("click", node=...)` runs a box's own `click` listener, but on a `text` node the listener does not run (the box around it receives the click). Whether a real pointer click on a text reaches the text's listener is not verified; until it is, a `Text` does not accept `On_Click` and the error says to put the handler on the box around it. #needs-verification on KWin.

- tre 0.6.1: a node's `shadows` is a list of `(color, dx, dy, blur, spread)`; the painted reach is measured in `tests/test_binder_shadow.py` (see Measurements). A shadow is clipped by the surface, so the margin must hold it.
- tre 0.6.1 (read in Tesserae UI's `listeners.py` and tre's docs, 2026-11-05): `node.on(event, handler)` keeps **one listener per event** (a second `on` replaces the first); a `click` bubbles to every ancestor's listener unless the handler calls `event.stop()` (the shell now stops it, as Tesserae UI's `handled` does); a layer surface draws only after the compositor's frame callback for its last frame, and a compositor may withhold callbacks for a surface it treats as hidden; `App.add_window` works while the app runs (a Panel's window is made on show); sway's headless backend has no pointer, so a real click cannot be injected there (`swaymsg seat ... cursor press` does nothing without a device).
- dbus-fast 3.1.2 on CPython 3.14.9 (GIL): `ServiceInterface` methods read their D-Bus signatures from string annotations, so a module that defines one must not use `from __future__ import annotations`.
- The headless sway prints `wgpu_hal::vulkan::swapchain::native: ... ERROR_SURFACE_LOST_KHR` on the shell's stderr at startup in some runs; it is the engine's, not the shell's log.
- `handle.call_soon` from a thread right after startup (before the loop has run for the first time) waited about 130 ms for a wake in one test; the known TRE-REQ-011 behaviour. A portal change that lands in the first 130 ms is applied late; later ones take 1 to 2 ms.
- sway (and by the protocol KWin): a layer surface with `exclusive_zone` 0 is placed inside the area the other surfaces' zones leave free, so its margins are measured from there; with -1 they are measured from the output's edge. Measured with a 40 px Bar and a 10 px top margin: zone 0 puts the surface at y 50, zone -1 at y 10 (`/tmp/zone_probe.py`, 2026-11-06). Panels were opened with 0 until now.
- tre 0.6.1: a node's `layout_x`, `layout_y`, `layout_width` and `layout_height` (`node.get`) are in the window's coordinates, not its parent's (a box at margin 30 inside a box at 16 reads 56 after nesting), and a `Window` has them before any frame.
