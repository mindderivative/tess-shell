# Common Keys and Conventions

> [!NOTE]
> The keys and value forms every shell file (written in TDL) shares. The language rules, the metadata block, the name registry and the monitor selectors are stated once in [TDL Language](TDL%20Language.md); this note links to them and lists only what a file author needs beside them. The decisions live in [ADR-0007 Shell UI Layer](../30%20Decisions/ADR-0007%20Shell%20UI%20Layer.md) and, for the file layout and the key names, [ADR-0014 Shell File Language > File Layout (Decided 2026-10-29)](../30%20Decisions/ADR-0014%20Shell%20File%20Language.md#file-layout-decided-2026-10-29). Examples are illustrations. Expressions are TEL's ([Expression Language Requirements](../40%20Specifications/Runtime/Expression%20Language%20Requirements.md)); the `{{ }}` slot that holds one is TDL's.

## Keys Every File Has

Every file starts with a metadata block between two `---` lines. The keys, the version format and who writes `UID:` are in [TDL Language > The Metadata Block](TDL%20Language.md#the-metadata-block); this table only names them.

| Key                       | Meaning                                                                                                                                       | Status                       |
|---------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------|------------------------------|
| `TDL`                     | The language version, a string. Required                                                                                                      | Decided (2026-10-29)         |
| `TEL`, `TRE`, `Shell`     | Minimum versions of the other projects (`Shell` is the Tesserae Shell release). A shell file requires all three; `TUIF` is only for a Tesserae app | Decided (D37, D38)           |
| `Name`                    | Required in every file (D39): the unique name of the file's root, the root of a dotted path (`RootShell.DP1.Top_Bar`), and in a module file the word that calls it | Decided (2026-10-30)         |
| `UID`                     | The file's shell-wide identifier (UUIDv7), written by the shell directly after the last version field                                         | Decided                      |

There is no file-type key. The root block names the file type: `Shell { }`, `Module { }`, `Style { }`, `Stylesheet { }`, `Theme { }` or `Settings { }`. A file has one root block, and it must agree with the suffix (D26; [TDL Language > The Root Block](TDL%20Language.md#the-root-block)).

File suffixes: `<Name>_Shell.tdl`, `<Name>_Module.tdl`, `<Name>_Style.tdl`, `<Name>_Theme.tdl`, `<Name>_Stylesheet.tdl`, plus a Python file `<Name>_Module.py` next to a module ([ADR-0007 Shell UI Layer > File naming (2026-10-25)](../30%20Decisions/ADR-0007%20Shell%20UI%20Layer.md#file-naming-2026-10-25)). The settings file is `settings.tdl`, with the root block `Settings { }` ([Settings File](Settings%20File.md)). A shell is one `*.tdl` file or a `Main_Shell.tdl` importing `<Name>_Shell.tdl` files. The syntax of blocks and properties is in [TDL Language > Punctuation](TDL%20Language.md#punctuation).

## Keys that Say what Something is

There is no `Type:`, no lowercase `shell:`, no `Kind:` on a surface and no `Block:` key. What a thing is comes from the root block (a file) or from the word before the brace (a block).

| Where                           | What says it                                                                                                | Values                                                                                                                                              | Status                                                  |
|---------------------------------|-------------------------------------------------------------------------------------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------|---------------------------------------------------------|
| A file                          | The root block                                                                                              | `Shell`, `Module`, `Style`, `Stylesheet`, `Theme`, `Settings`                                                                                       | Decided (2026-10-30; replaces the file-type key)        |
| A surface                       | The block head                                                                                              | `Bar`, `Frame`, `Panel`, `Popup` ([Surface Types](../40%20Specifications/Surfaces/Surface%20Types.md))                                                                                                | Decided (2026-10-29; replaces `kind:`)                  |
| A building block                | The block head                                                                                              | Box, FlexBox, Grid, Text, TextField, Bitmap, SVG, Square, Rectangle, Triangle, Hexagon, Circle, Ellipse, Ring, Path, Terminal, Canvas ([Building Blocks](../50%20Design%20System/Building%20Blocks.md)) | Decided (2026-10-29; replaces `block:`)                 |
| A module call                   | The block head, which is the `Name:` in the module file's metadata                                           | `Clock { }`; params are keys inside, written as the module declared them (D18)                                                                                                     | Decided (2026-10-29); repeats allowed, ordered by position |
| A monitor                       | The block head `Monitor`                                                                                    | Selectors are in [TDL Language > Monitors (Shell Schema)](TDL%20Language.md#monitors-shell-schema)                                                                                                          | Decided (2026-10-29; replaces `root`)                   |

- All of these names are in one registry. A name registered twice is a load error, except that a user module of the same name overrides a shipped module ([TDL Language > Names and the Registry](TDL%20Language.md#names-and-the-registry)).
- `Name:` is the unique name of a block, surface or module. A block can be placed anywhere `Children` is allowed: on a surface, in a container, in a module or in a popup (decided 2026-10-27).
- `Kind:` has one meaning: it references a type by its exact name where a type is named by value (`Kind: Panel`, `Kind: Clock`). A style class that applies to text writes `Kind: Text` ([Style, Theme and Stylesheet Files > Classes](Style%2C%20Theme%20and%20Stylesheet%20Files.md#classes)). There is no `Kind: Block` and no `Kind: Module`.
- `widget:` and `module:` no longer exist as keys. The word "module" is a root block (`Module { }`) and a registry name.
- Case: keys, block heads and structure words are Capitalised; enum values are full upper case (`Layer: OVERLAY`); `true`, `false` and `null` stay lowercase ([TDL Language > Names and the Registry](TDL%20Language.md#names-and-the-registry)).

## Structure Keys

| Key                          | Where                                                  | Meaning                                                                                                                                                                                                                                                        | Status                                                                                                                                                                                  |
|------------------------------|--------------------------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `Shell`, `Module`, `Style`    | The root block of a file                               | The one root block of a file; it names the file type and must agree with the suffix ([TDL Language > The Root Block](TDL%20Language.md#the-root-block)). `Style` is the root of a style file and also an inline block on a surface, module or block                                              | Decided (2026-10-30)                                                                                                                                                                    |
| `Monitor`                    | Inside `Shell`                                         | The tree of one monitor's surfaces; several per file. Keys: `Name`, a selector (`Index`, `Connector`, `Description`), `Children` ([Shell File](Shell%20File.md))                                                                                                              | Decided (2026-10-29)                                                                                                                                                                    |
| `Children`                   | A Monitor, a surface, a container, a popup             | A block of entries: blocks and module calls (the same head may repeat, ordered by position), `Import` properties, and `If` and `For` blocks ([ADR-0014 Shell File Language > Conditions and Repeats (Decided)](../30%20Decisions/ADR-0014%20Shell%20File%20Language.md#conditions-and-repeats-decided)). The only holder of contents; `modules:` is gone | Decided                                                                                                                                                                                 |
| `Import`                     | Inside `Children`; a shell file; a module file; an inline `Style` | One file name or a list. Inside `Children` it brings in `<Name>_Shell.tdl` surfaces or embeds a `<Name>_Module.tdl` at that position, which is how modules nest; inside `Style` it imports a style file. Paths are relative to the importing file; imports nest | Decided                                                                                                                                                                                 |
| `If`, `Else`, `For`, `In`, `Key` | Inside `Children`                                  | Conditions and repeats; the forms are in [TDL Language > Structure Words](TDL%20Language.md#structure-words)                                                                                                                                                                                       | Decided (2026-10-29)                                                                                                                                                                    |
| `Params`                     | A module file declares them; a use passes them         | Typed values                                                                                                                                                                                                                                                   | Decided that they exist and where they sit (D17); the type names are proposed                                                                                                                                            |
| `Tooltip`                    | A module use; a block or surface when written by hand  | A Popup file name or an inline Popup, opened as that thing's tooltip. Available on every module, built-in and custom, with no module code ([Popup > Tooltips (decided 2026-10-28)](../40%20Specifications/Surfaces/Popup.md#tooltips-decided-2026-10-28)). On a Popup entry, `Tooltip: true` makes it a tooltip                      | Decided (2026-10-28); the unique-name form is proposed                                                                                                                                  |
| `Style`                      | A surface, a module                                    | A style file name, or an inline `Style { }` block of style values                                                                                                                                                                                              | Decided                                                                                                                                                                                 |
| `Padding`                    | An element that has `Children`                         | Transparent space between the children and the element's four sides; four-sided, left, top, right, bottom (D41 to D45)                                                                                                                                         | Decided (2026-10-30)                                                                                                                                                                    |
| `Margin`                     | An element; a Panel and a Frame on their own terms     | Transparent space around the element itself; four-sided. A Bar has none. On a Frame it adds to the Frame's size ([Shell File > Surface Keys](Shell%20File.md#surface-keys))                                                                                                                  | Decided (2026-10-30)                                                                                                                                                                    |
| `Gap`                        | A Bar, a Popup, a Panel with a non-Frame target        | The distance to the thing the surface is attached to; never a layout's child spacing (D49)                                                                                                                                                                      | Decided (2026-10-30)                                                                                                                                                                    |
| `Offset`                     | A Bar                                                  | One number that moves it along its `Edge`: positive towards the end, negative towards the start (D87) | Decided (2026-10-30) |
| `Inset`                      | A Panel                                                | Four-sided (left, top, right, bottom): positions it from its anchored edges (D89) | Decided (2026-11-02) |
| `Spacing`                    | A layout (`Flex`, `Columns`, `Rows`)                   | The space between a layout's children (D49)                                                                                                                                                                                                                     | Decided (2026-10-30)                                                                                                                                                                    |
| `Layer`                      | A surface                                              | `BACKGROUND`, `BOTTOM`, `TOP`, `OVERLAY`, numbered 0 to 3 as in the protocol; `OVERLAY` is the highest. A Bar or Panel may use `BOTTOM`, `TOP` or `OVERLAY`; a Frame only `TOP`; a Popup stacks above its parent                                               | Decided (the key and the four values, flow diagram 2026-10-26). Only `TOP` surfaces may reserve space (`Exclusive_Zone`). `BACKGROUND` is for wallpapers only, for now: no surface type uses it |

## Names and References

- A `Name` is unique across the shell (maintainer, 2026-10-26) and reachable from anywhere through the registry, nested or not. Anything with a unique name gets a UID. A definition that is used many times (a module, an imported surface set) has local names inside it; each use gets a path name such as `top_label.Label_Text` (proposed, [ADR-0007 Shell UI Layer > Open items](../30%20Decisions/ADR-0007%20Shell%20UI%20Layer.md#open-items)).
- Each use of a module is an instance. Python keys it as `Clock@<uid>`; the shell writes `UID:` into the use in the file only when the user asks for stable identity across reordering ([TDL Language > Names and the Registry](TDL%20Language.md#names-and-the-registry)).
- A reference to a name in another file is resolved through the registry: a Panel attached to a Bar names the Bar. An unresolved reference is an error at load; a target that disappears while running is a warning and the Panel stays hidden until it returns ([ADR-0007 Shell UI Layer > Config directory and registry (2026-10-25)](../30%20Decisions/ADR-0007%20Shell%20UI%20Layer.md#config-directory-and-registry-2026-10-25)).
- Surfaces do not nest. They are siblings and refer to each other by name.
- A UID can also address a file; Python reaches a module's TDL by file name, unique name or UID.

## Value Forms

The value forms are stated once in [TDL Language > Values](TDL%20Language.md#values); this table adds how the shell uses them.

| Kind                                                        | Forms                                                                                                                                            | Notes                                                                                                       |
|-------------------------------------------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------|-------------------------------------------------------------------------------------------------------------|
| Colour                                                      | `"#RRGGBB"`, `"#RRGGBBAA"` (quoted, because `#` starts a comment), `rgba(0 0 0 0.5)` (space separated; red, green and blue 0 to 255, alpha 0.0 to 1.0), a theme token reference such as `$color.on_surface`, a plain string the style engine resolves by theme key (D16, [Style Schema > Theme Tokens](Style%20Schema.md#theme-tokens)) | The shell converts to tre's `(r, g, b, a)` with 0 to 255 integers ([Value Types and Conversion](../42%20Python%20API/Value%20Types%20and%20Conversion.md)) |
| Four-sided values (borders, corner radii, margins, padding) | One number for all sides; a list of four in the order left, top, right, bottom (D50), `[2, 2, 2, 2]`; named sides as a block, `Margin { Left: 2, Top: 2, Right: 2, Bottom: 2 }`. A list of two or three items is an error (`bad-sides`) whose hint says to use one number, four items or named sides, and that CSS orders its sides top, right, bottom, left and accepts two or three. The order matches Flutter, Qt and WPF and differs from CSS and SwiftUI #needs-verification. The shell reorders to tre's order (top, right, bottom, left) when it passes a value to tre | The brace-only form `{2, 2, 2, 2}` is not used (PyYAML read it as `{2: None}` on 2026-10-26; in TDL a brace opens a named block) |
| Size                                                        | A whole number of pixels, a percentage `50%`, `AUTO`, `EXPAND` where a key allows them (D34); a percentage plus pixels (tre's `calc(100% - 16)`) is not in v1 (D6) | Lengths have no unit suffix; a float is only for non-lengths such as `Opacity: 0.9` (ADR-0014). The forms tre accepts |
| Text, numbers, booleans                                     | Unquoted words are strings; quote text that holds a `,` or a closing brace; `"..."` or `'...'` with `\` escapes                                   | `true`, `false` and `null` are bare words that the key's schema type reads as boolean or null; `[]` is the empty list (D2)                                                        |
| Lists, blocks                                               | `[a, b]` lists; `Head { ... }` blocks, one-line `Spacer { }` allowed (D8)                                                                                                            | A list feeds a `For` repeat; no unnamed block as a list item, no numeric keys (D4); a repeated key in one block is an error naming both places (D9)                                                                                 |
| Expression                                                  | A `{{ ... }}` slot on one line, no quotes; TEL evaluates it                                                                                      | Reads `params.<name>` and values the module sends                                                           |

## Errors

Every error carries `file:line:column`, from the shell's own TDL parser (ADR-0014) and says what is wrong and what to write (AGENTS > 3. Layering principle). The syntax errors and their proposed codes (`tdl-no-metadata`, `tdl-unclosed-block` and the rest) are listed once in [TDL Language > Errors](TDL%20Language.md#errors); that list is a proposal the maintainer has not decided. Errors that apply to every file beyond syntax: a root block that does not match the suffix (both named; `shell-root-suffix`); an unknown key; a head word that is not in the registry; a name defined twice (both places named); an import cycle (the chain of files printed); a missing file; a param of the wrong type; a four-sided value with two or three items (`bad-sides`, a schema error with the short slug form of [Validation and Errors](../40%20Specifications/Runtime/Validation%20and%20Errors.md), not a syntax error with a `tdl-` prefix). The full list is in [Validation and Errors](../40%20Specifications/Runtime/Validation%20and%20Errors.md).

## For Readers Who Know Other Frameworks

Some words here mean something other than they do elsewhere. This table lists them so a reader does not carry over the wrong meaning. A statement about another framework that has not been checked against its documentation is tagged #needs-verification.

| Word or form         | What it means here                                                                                                                                                                                       | Elsewhere                                                                                                                                                                                              |
|----------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `Gap`                | The distance from a surface to what it is attached to: an edge, a Bar or another surface                                                                                                                 | Not CSS `gap`. For the space between children, use `Spacing`                                                                                                                                           |
| Four-sided values    | One number, a list of four in the order left, top, right, bottom, or named sides. A list of two or three items is an error, and its hint says to use one number, four items or named sides | The order matches Flutter, Qt and WPF and differs from CSS and SwiftUI. CSS orders its sides top, right, bottom, left and accepts two or three items #needs-verification                               |
| Lengths              | Logical pixels with no unit: `16`. A percentage is a whole number with a sign: `50%`. A float is never a length                                                                                          | CSS writes a unit, such as `16px` #needs-verification                                                                                                                                                  |
| Colour `"#RRGGBBAA"` | The alpha is last: `"#ff000080"` is red at half opacity                                                                                                                                                  | Qt, Android and Flutter put the alpha first; CSS puts it last #needs-verification                                                                                                                      |
| `rgba(r g b a)`      | The values are separated by spaces, not commas: `rgba(255 0 0 0.5)`. Red, green and blue run 0 to 255, alpha 0.0 to 1.0                                                                                  | CSS has long written commas #needs-verification                                                                                                                                                        |
| `AUTO` and `EXPAND`  | On a `Width` or `Height`, `AUTO` fits the content and `EXPAND` takes the free space. On a surface, `EXPAND` stretches along the edge the surface is attached to                                          | The closest matches: CSS `auto` and `flex-grow`; Android `wrap_content` and `match_parent`; Flutter a shrink-wrapped widget and `Expanded`; Figma Hug and Fill. They are not exact #needs-verification |
| `Tooltip`            | One word, two uses. On a Popup, `Tooltip: true` makes the Popup a tooltip. On a block or a module use, `Tooltip` names the tooltip Popup to show                                                         | The block it is written in tells which use it is                                                                                                                                                       |
| `Border`             | A border takes layout space: the content and the children sit inside it                                                                                                                                  | A CSS border takes space too; a stroke that is only painted over an edge, as in SVG, does not #needs-verification                                                                                      |
| `Panel`              | A general surface: it can float, attach to another surface or sit at an edge                                                                                                                             | What KDE Plasma calls a panel is a Bar here                                                                                                                                                            |
| `Bar`                | A surface attached to one screen edge that reserves space: a top bar, a dock or a side bar                                                                                                               | The Plasma panel is the nearest match                                                                                                                                                                  |
| `Visible`            | `true` by default. `Visible: false` starts a surface hidden                                                                                                                                              | The same sense as `visible` in QML #needs-verification                                                                                    |
| `Flex`               | The stacking direction of a FlexBox: `HORIZONTAL` or `VERTICAL`                                                                                                                          | Not CSS `flex` (grow and shrink); CSS calls the direction `flex-direction`, Flutter `direction`, Android and Qt `orientation` #needs-verification |
| `Frame`              | A surface that runs around the screen edge and reserves space on all four sides                                                                                                          | Not a plain container as in Figma or Qt #needs-verification |
| `Focused` (style state) | Applies while a block has keyboard focus, not mouse focus                                                                                                                              | CSS `:focus-visible` is the match; CSS `:focus` also fires for a click #needs-verification |
| `On_Unfocus`         | Fires when a block loses focus                                                                                                                                                           | CSS calls it `blur` #needs-verification |
| `Position`           | `RELATIVE` keeps the block in the layout and ignores `Left`, `Top`, `Right` and `Bottom`; `ABSOLUTE` takes it out of the layout and places it by those                                   | CSS `relative` shifts the block by its offsets, and CSS calls the in-flow default `static` #needs-verification |
| `Offset`             | One number that moves a surface along its edge: positive towards the end, negative towards the start (D87)                                                                               | Compose and SwiftUI `offset` move a shape without changing layout; CSS `inset` sets sides #needs-verification |
| `Elevation`          | A percentage: `0%` no shadow, `100%` a shadow of about 64 px                                                                                                                             | Flutter, Compose and Android use a continuous distance in dp; Material 3 uses levels 0 to 5 #needs-verification |
| `Label`              | A module for short text; the accessibility name is a separate key, and `Type.Label` is a text style                                                                                      | SwiftUI `Label` is an icon with text; HTML label captions an input #needs-verification |
| `START` and `END`    | The left or top side and the right or bottom side, in a left-to-right layout. There is no right-to-left mode in v1                                                                       | CSS, Compose and SwiftUI follow the text direction #needs-verification |

## Open

- [ ] What a version change of `TDL:` or of a version pin means (the format is a string, `0.1`).
- [x] Case rules: keys and block heads are Capitalised, enum values full upper case (D33), `Kind:` takes an exact name ([ADR-0014 Shell File Language > Layout Rules](../30%20Decisions/ADR-0014%20Shell%20File%20Language.md#layout-rules), items 4, 10, 11 and 13).
- [x] Unknown keys are errors (decided 2026-10-28, [Validation and Errors](../40%20Specifications/Runtime/Validation%20and%20Errors.md)); unknown metadata keys are kept and ignored (ADR-0014, item 14).
- [x] The expression delimiter: `{{ }}` on one line (ADR-0014, 2026-10-29). The expression syntax inside it is TEL's.
- [x] Whether a block is named by the word before the brace or by a key: the head is the type and `Name:` is the unique name (ADR-0014, item 6).
- [ ] Units beyond pixels (a scale-aware unit).
- [x] A TDL form for a percentage plus pixels: none in v1; it waits for a surface that needs it (D6, [ADR-0014 Shell File Language > Decisions on the Open Items (2026-10-30)](../30%20Decisions/ADR-0014%20Shell%20File%20Language.md#decisions-on-the-open-items-2026-10-30)).
- [x] Boolean and null spellings: bare `true`, `false`, `null`; `[]` is the empty list (D2).
- [ ] How a repeated use names itself in the file; see [TDL Language > Open](TDL%20Language.md#open).

## Acceptance Criteria

- [ ] A four-sided value written as a list of two or three items is refused with the slug `bad-sides`, and the hint says to use one number, four items or named sides and that CSS orders its sides top, right, bottom, left and accepts two or three; one number, four items and named sides load.
