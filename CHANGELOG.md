# Changelog

## Unreleased

- Package skeleton: `pyproject.toml`, `src/tess_shell`, tooling (ruff, mypy, pytest).
- Command line `tesserae-shell` with `version`; `run` and `check` are wired in later tasks; the other subcommands report "not implemented in M0".
- Config directory lookup (`--config-dir`, `$XDG_CONFIG_HOME`, `~/.config`) and `settings.tdl` reading: every key of the Settings File note, one finding per problem with `file:line:column`.
- Loguru setup: console sink and a daily `log_YYYY-MM-DD.log` (directory 0o700, file 0o600), JSON option, midnight file swap, retention, console-only fallback.
- Instance lock (`flock` on `$XDG_RUNTIME_DIR/tesserae-shell/lock`, exit 4 naming the holder's pid) and `$XDG_RUNTIME_DIR` checks (exit 2).
- `tesserae-shell run`: pre-flight, settings, logging, instance lock, registry (`registry.json`, created and saved atomically), then the engine loop with `keep_alive`; SIGTERM and SIGINT stop it cleanly (exit 0), a second signal forces exit 130. Steps 7 to 12 of the start sequence that need later milestones are logged as not built.
- `tesserae-shell check`: settings, then a syntax check of every `*_Shell.tdl`, `*_Module.tdl`, `*_Style.tdl`, `*_Theme.tdl` and `*_Stylesheet.tdl` under the search directories, with `file:line:column`, `--json`, exit 0, 1 or 2. `run` step 7 does the same scan.
- Idle measurement script `tests/perf/measure_idle.py` and its first result (`tests/perf/idle-results.md`): 0.000 % of one core and about 3 wake-ups per second over 60 s, within the budgets.
- Import rules of the package layout are enforced by `tests/test_imports.py`.
- M1 binder (`tess_shell.binder`): the typed tree and `BindError` (`model.py`).
- M1 binder converters (`convert.py`): length, bound, number, whole, positive, bool, text, color, enum, wrap flag, sides, radius, font family, plus a colour parser; table-driven tests.
- M1 binder tables (`tables.py`) for `Box`, `FlexBox`, `Text`, `Rectangle`, `Spacer` and `SVG`, guarded by a test that builds a node for every row on a headless tre window; `build.py` binds a typed tree through `Window.build`, collects every error with its `file:line:column`, translates tre's errors back to the key, refuses `If` and `For`, and returns a `View` with `dispose`.
- M1 Bar geometry (`surfaces/bar.py`): `bar_geometry(spec, output, content)` computes tre's `anchor`, `size`, `margin`, `exclusive_zone` and `exclusive_edge` as a pure function; every row of the worked-examples table is a test, with `ZeroSize` for a Bar that is not created.
- Text `Width`/`Height` `AUTO` becomes tre's `"fit-content"`; a test pins that a headless `LayerWindow` accepts the Bar geometry of every worked example.
- Binder: a key written both in a block and in its Style is an error naming both places (D2); a Font_Family list is joined with ", " (D5).
- M1 schema (`tess_shell.schema`): `read_shell` checks a parsed `*_Shell.tdl` against the `Shell`, `Monitor`, `Bar` and block key declarations and types it into the binder's model; unknown keys with nearest names, wrong types, missing keys, duplicate names and monitors, `style-duplicate`, `bad-sides`, `Border { }` flattened, forms not built in M1 refused (`not-built`; Bar keys M1 does not build are warnings). `tree.py` moved from `files` to `schema`.
- M1 files: stage 3 header checks (`version-pin`, `shell-root-suffix`); `check` and `run` step 7 now type every `*_Shell.tdl`, print warnings without failing, and a test pins that the schema's key declaration matches the binder tables.
- M1 surfaces (`surfaces/manager.py`): `assign` matches `Monitor` blocks to outputs (Connector, then Description, then Index; `Index: default` takes the rest), `SurfaceManager` opens one `LayerWindow` per Bar (namespace `tesserae-shell.bar.<name>`, geometry from `bar_geometry`, inline `Fill`), binds its children and logs every bind error while leaving that Bar empty; `run` steps 10 and 11 call it. Tests on a private headless sway: the Bar is configured at 1280x32, the output's usable area shrinks by the reserved zone and is restored when the shell stops.
- M1 measurements: `tests/perf/measure_bind.py` (`bind-results.md`) and `measure_idle.py --bar` (`idle-results-bar.md`): 3,101 nodes bind in about 12.6 ms, the example in 0.03 ms; idle with the Bar shown is 0.000 % of one core and about 2.7 wake-ups per second.
- A Monitor block that names an output an earlier block already took logs a warning naming both blocks at start; the first wins (D11).
- A reference image of the M1 example (`tests/snapshots/m1_example.png`, 400x32) compared with a tolerance of 0.2 % of the pixels (a recoloured icon fails it); `UPDATE_SNAPSHOTS=1` regenerates it, written by `tess_re.snapshot.write_png`. The sample SVG now uses `currentColor`, so its `Color` is visible.
- M2a binder: `SlotValue`, `SlotPart` and `UseNode` in the typed tree (the binder refuses them unevaluated), and `View.update` sets new typed values on named nodes through one `Window.apply`, skipping values a node already has.
- M2a schema: `read_module` types a `*_Module.tdl` (`Module { Params { } Children { } }` or one layout block; param types string, number, boolean with defaults), a `{{ }}` slot in a value becomes a `SlotValue` whose parts carry the origin of the slot text, and a block headed by a module's call name is a `UseNode` with typed params (unknown param with nearest names, missing param without default, slot in a param refused). `Style`, `Import` in a module are refused until M2b.
- M2a model: `model/store.py` (thread-safe `ValueStore`: queued sends, one wake per turn, latest value per use and key, plain-data check), `model/expand.py` (a module call becomes the module's layout with per-use node ids), `model/live.py` (slots compiled with their origin, evaluated in the use's scope, links re-evaluated only when a read path is touched; an error keeps the last value and logs `file:line:column`).
- M2a modules: `from tess_shell import Module, action`; `modules/host.py` imports `<Name>_Module.py`, finds exactly one `Module` class, sets `ctx` before `start()`, validates each use, and isolates failures (missing `.py`, no or two classes, import error, `start()` raising: a finding naming the files and the line; other modules keep running); `modules/ticks.py` is the shared wall-clock source (one thread, woken only at a subscribed second or minute, no drift, a clock moved back is handled).
- M2a Clock: `shipped/Clock/Clock_Module.tdl` and `.py` (`format`, `hour_cycle`, `timezone`; `--:--` fallback); a user module of the same name overrides a shipped one. `run` steps 10 to 12 expand the module calls, load and start the modules, build the Bars from their first values and update only the changed node properties, one `Window.apply` per Bar per turn.
- M2a files: a module call may sit anywhere in a Bar or a module's layout, `Import: <path>_Module.tdl` (one file or a list, relative to the importing file) embeds a module at that position, modules are read in two passes so the order of files does not matter, and a circle of calls or imports is an error naming the chain (`import-cycle`). A module's `UID` is written into its metadata (and the shell file's) on first registration, after a backup under `$XDG_STATE_HOME/tesserae-shell/backups`, and kept in the registry as `file:<path>`.
- M2a measurement: idle with the Clock shown is about 2 wake-ups per second between ticks (tre's own thread); the tick adds a burst from tre's software renderer (`tests/perf/idle-results-clock.md`).
- M2b binder: `View.rebuild(nodes)` compares a new typed tree with what is built by key (the `Name`, else block word and position), keeps matching nodes, sends the changed properties in one `Window.apply`, builds new subtrees with `Window.build`, reorders with `set_children` and frees removed nodes; a changed block word or a property the new tree no longer sets is a replacement; a bad value changes nothing.
- M2b `If`/`Else` and `For` in a module's layout (B1): the schema types them, `model/live.py` evaluates the condition and the repeater with TEL (`select_tracked`, `compile_repeater_parts`, `reconcile_tracked`, `RepeaterState` kept between resolves, entry names `<name>_0001` never reused), and a use with structure is resolved again and handed to `View.rebuild` when anything its slots, conditions or headers read changes; a key nothing reads causes no rebuild. A module call or `Import` inside `If`/`For`, and `If`/`For` outside a module, are not built yet.
- M2b module style files (B4): `Style: <Name>_Style.tdl` (relative to the module file) or an inline `Style { }` in a module, with `Classes { name { Kind: Text, ... } }` and per-type defaults; `Class: name` (one or a list) on a block; priority is the file's type default, then its classes, then the block's inline `Style`, then keys written on the block. A missing class, a class of another block type, a missing or bad style file are errors at their own file and line. The shipped Clock now takes its look from `Clock_Style.tdl`.
- M2b icon sets (B5): `SVG { Icon: "mdi:account" }` (or a bare name) is resolved from Iconify-style JSON sets in the config `Icons` folder, then `Directories { Icons: [...] }`, read on the first lookup (the real 7,447-icon `mdi` file: 5 ms), a prefix selects a set and no prefix looks in `mdi` first; the body draws with `currentColor`, so `Color` tints it; an unknown icon is an error at its value with the nearest names; an SVG needs `Source` or `Icon`, not both. No set ships in the package (the licence texts travel with the files).
- M2b file watcher (B2): `watch.py` blocks in `select` on one inotify descriptor (`inotify_simple`), listens for close-write, moved-to, moved-from and delete, ignores dot files, `~`, `.swp`, `.tmp`, `.bak` and the `schemas`, `logs`, `backups` folders, watches folders created later, and calls back once with the changed paths after 200 ms of quiet; the shell's own writes are recognised by content hash and dropped; a watch that cannot be added (the limit) turns `ok` off with a warning.
- M2b hot reload (B3): `reloader.py` validates a change on the watcher thread exactly as at start (settings and every shell file) and queues the apply onto the loop only if there is no error; an error changes nothing and is reported with `file:line:column`. The apply brings the modules to the new definition (`ModuleHost.sync`: a module no longer used is stopped, a new one is loaded, a changed `.py` is imported first and replaces the instance only if the import works, a changed module or style TDL file calls `reload()` and keeps the instance, uses are added and removed with `use_added`/`use_removed`), then each Bar is kept (tree rebuilt by the keyed diff, geometry set live in one `set()`) or closed or opened. `SIGHUP` reloads everything (also with `Hot_Reload: false`); `Hot_Reload` and `Reload_Debounce` are settings; a change to `Directories`, `Registry` or `Main_Shell` is reported as needing a restart and `Logging` applies at once. Module code is compiled from source on every load, never from a bytecode cache. The shell's own UID writes are recognised by content hash (one use, five seconds) and dropped. `scanner.py` holds what `check`, `run` and a reload share.
- M2b measurements: `tests/perf/measure_reload.py` (`reload-results.md`): a saved `Height` is applied a median of 206 ms after the save (200 ms debounce plus about 5 ms to validate, diff and set); `idle-results-clock.md` is re-measured with the watcher thread running: no change in wake-ups attributable to it.
- Binder: a `Text` with no `Width` is sized to its content (`fit-content`); tre laid such a text out at width 0, so two texts in a row (two Clocks) overlapped. M1's single text hid it.
- Reload: the log line says `reloaded with errors (...)` when a module's Python or layout failed to import and the old instance was kept.
- M3a: `Elevation: N%` and `Shadows { Shadow { Color, X, Y, Blur, Spread } }` on FlexBox, Box and Rectangle (and in an inline Style); the default `Max` reaches 64 px, and `binder/shadow.py` computes the transparent margin a shadow needs (measured against tre 0.6.1: blur + spread +/- offset, plus one pixel).
- M3a: the Settings portal reader (`services/portal.py`) on a `dbus` service thread (`services/bus.py`, dbus-fast): one `ReadAll` at start, then `SettingChanged` only; settings.tdl gains `Appearance { Theme, Stylesheets, Follow_Desktop }`.
- M3a: a Bar with `Elevation`, `Shadows` or `Shadow_Bleed` in its `Style` is drawn as a body inside a larger transparent surface (ADR-0010): the surface grows by the shadow margin, the exclusive zone grows by the same amount on the Edge side so the reserved space is unchanged, and a reload that changes the elevation only sets properties. Every Bar now has a body node that holds its fill.
- M3a themes (A1): `Themes/<Name>_Theme.tdl` with the token groups `Color`, `Type`, `Shape`, `Space`, `Elevation` and `Motion` and `Modes { Light, Dark, High_Contrast, Reduced_Motion }`; a style value `$group.name` (any key of a block or an inline `Style`) is a reference, read as the kind of the key that names it, resolved just before binding; a missing token or one of the wrong kind is an error at its line with the nearest names, in `check` as well as at run time. The shell ships a `Default` theme (dark base, light and high-contrast modes, `Accent: DESKTOP` follows the desktop) and a `Default` stylesheet (text and icons take the theme's colours); `Appearance { Theme: <Name>, Stylesheets: [<Name>, ...] }` in settings.tdl names the ones in use, and a reload applies a change.
- M3a stylesheets (A2): `Stylesheets/<Name>_Stylesheet.tdl` with `Rule { Selector: "Text" | ".class" | "#name", <style keys> }`, a name beating a class beating a type and the later rule winning a tie; the block's own style and keys beat a rule, and a key the block does not take is skipped. Selectors with a `:state` or `::part` are read and skipped with a warning (the events layer, M3b).
- M3a portal (A3): the desktop's colour scheme, accent, contrast and reduced-motion settings pick the theme's mode (`Light`, `Dark`, `High_Contrast`, `Reduced_Motion`, durations to 0) and a change rebuilds the Bars by the keyed diff, 1 to 2 ms after the `SettingChanged` signal; `Appearance { Follow_Desktop: false }` never calls the portal; no portal gives the defaults and one warning.
- Tests that start the shell no longer see the real session bus (`DBUS_SESSION_BUS_ADDRESS` is dropped from the private compositor's environment); the portal tests run a private `dbus-daemon` with a fake Settings portal.
- M3a measurement: `tests/perf/measure_shadow.py` (`shadow-results.md`): a 100 % elevation on the example Bar grows its surface from 32 to 97 px and the process by 0.8 MiB.
- M3b events (B1, first part): `On_Click: action_name` or `On_Click { Action: name, Arg: value }` on a `FlexBox`, `Box`, `Rectangle`, `Spacer` or `SVG` in a module's layout calls the module's `@action` method on the loop thread with a `tess_shell.Event` (`name`, `use`, `args`, `time`, pointer `x`/`y`, `button`); all twelve event keys are known (an unknown one names the nearest, one a block cannot raise says so, the shell's built-in actions `Show`, `Hide`, `Toggle`, `Close`, `Call` are `not-built` until the Panel); a handler naming a method that is not an `@action` fails the module's load with the action list; a handler that raises is logged with the module, event and position and the shell keeps running; a handler over 50 ms is logged as slow; a reload replaces a handler without a second listener. A `Text` takes no listener in tre 0.6.1, so it raises nothing: put the handler on the box around it.
- A theme that lacks a token falls back to the `Default` theme's value for it, token by token, in the current light/dark look (D42); a token neither defines is still an error.

- M3b B1 (first part): `On_Click: action_name` or `On_Click { Action: name, Arg: value }` on a `Box`, `FlexBox`, `Rectangle`, `Spacer` or `SVG` in a module's layout calls the module's `@action` method on the loop thread with a `tess_shell.Event` (`name`, `use`, `args`, `time`, pointer `x`, `y`, `button`). An unknown `On_` key names the nearest of the twelve v1 events, an event a block does not raise, a built-in action (`Show`, `Hide`, `Toggle`, `Close`, `Call`; built with the Panel) and a bare name in a shell file are load errors, a handler naming a method that is not an `@action` fails the module's load with the module's actions listed, and a handler that raises is logged with its module, event and position without stopping the shell. A reload replaces a handler without a second listener. tre 0.6.1 delivers a click to a text node's parent and not to the text's own listener, so a `Text` raises nothing: put the handler on the box around it.
- A partial theme falls back to the `Default` theme's value for any token it lacks, token by token, in the Default's current light or dark look (maintainer, D42); a token neither defines is still an error.
- A rule with a module's name as its selector (`Selector: "Clock"`) styles the module's root blocks at every use; inner blocks are styled by a type, class or `#name` rule (D40).
- The `mdi` icon set (Material Design Icons, Pictogrammers, 7,447 icons) ships in the package as `shipped/Icons/mdi.json` with its licence text (`MDI-LICENSE.txt`) and a `NOTICE.txt`; it is searched after the user's `Icons` folders, so `SVG { Icon: "mdi:account" }` works with no setup and a user set of the same prefix wins.
- Fix: a Bar's shadow margin no longer takes pointer input. The surface's `input_region` is the body (ADR-0010; Panel > Input region) when there is a margin, and the whole surface when there is none; a reload that adds or removes the shadow sets it live. Before this the transparent area below a shadowed Bar blocked clicks on the windows under it (found on KWin).
- M3b Panel (B2, first part): `Panel { Name, Layer, Anchor, Inset, Width, Height, Keyboard, Input_Region, Visible, Hide_After, Style, Children }` in a Monitor's `Children`; an anchored Panel is placed by `Inset` (left, top, right, bottom, reordered to tre's margin), a Panel with no `Anchor` is centred by the compositor, a size of 0 stretches between two opposite anchors; a shadow grows the surface and the body keeps its place, and the input region is the body (`Input_Region: []` passes clicks through, `AUTO` is the drawn shapes). `Visible: false` opens hidden; `Hide_After: 1500` hides it after that many milliseconds and showing it again resets the timer; Escape hides a Panel that takes the keyboard. **Hiding (D44, revised 2026-11-05):** a hidden Panel has no window; showing makes a new one from the same Panel record and builds its tree again from the current values. `On_Click { Action: Show | Hide | Toggle, Target: <Panel Name> }` on a block, in a shell file or a module's layout, runs the shell action; a `Target` that names no Panel is an error with the nearest names. Not built yet: `Attach_To`/`Attach`/`Alignment`/`Gap`, `Movable` and saved positions, `Animation`, `Exclusive_Zone`, `Input_Region` rectangles, `AUTO` size, `Meld`, and the Panel's own `On_Open`, `On_Visible` and the other surface events.
- Tests: the live reload test no longer reads the workspace top after the Bar may already have reserved its zone (a race that made it fail one run in five).

- A Panel's `Style` takes `Corner_Radius`, `Border_Width` and `Border_Color` (applied to its body) as well as `Background`, `Elevation`, `Shadows` and `Shadow_Bleed`; a Bar's `Style` does not.
- Panel: hiding now closes the window and showing makes a new one (D44, revised). The first version kept a transparent surface mapped; on KWin a hidden Panel kept showing and a shown one sometimes stayed empty (the maintainer's check), and clicks felt late. A `Visible: false` Panel never has a surface until it is shown, so there is nothing to go stale and no first-show flash. At DEBUG the shell logs each pointer press and release per surface, each dispatched action, and the time of a new Panel's first frame.
- A handler stops its click at the first listener (as Material 3 and Tesserae UI do): a clickable inside a clickable takes its click alone.
- The `Default` theme is now a dark blue-grey with steel blue as its Primary (`#5B97C9`, 5.8:1 on the surface) and `#4682B4` as its Accent; its light variant uses `#2F6B9A`, its high-contrast variant black and white with a light blue (maintainer, D33). `Accent: DESKTOP` still follows the desktop's accent.
- `settings.tdl` `Debug { Panel_Hide: CLOSE | KEEP }` (a restart applies it): CLOSE, the default, hides a Panel by closing its window; KEEP is the first version, which keeps the surface mapped and draws nothing, kept to find why it was not repainted on KWin (D44). At DEBUG the shell logs the first frames a Panel draws after each show or hide, and the frame count 250 ms later, in both modes.
- The surface manager wakes tre's loop (a queued no-op) after it changes a window: a Panel shown or hidden, a reload, a theme change, a value update. tre 0.6.1 does not request a frame for a window whose node was changed during a callback of another window, so the change waited for some other wake (measured on a private sway with `tests/kwin/probe_hide.py`: a child node's fill changed from another window's timer was not drawn in 500 ms, and was drawn in 1 to 2 ms when followed by `call_soon`). This is the likely cause of the first hide route failing on KWin (the KWin log shows no frame after a show until the 250 ms debug timer).
- The default way to hide a Panel is now the kept surface (maintainer, 2026-11-06): the surface stays mapped and draws nothing, so a hidden Panel keeps its tree and state; `Debug { Panel_Hide: CLOSE }` selects the window-closing route. The kept surface works because the shell wakes tre's loop after each change it makes to a window; the maintainer checked it on KWin. The underlying fault is tre's and is written up as TRE-REQ-012 (`tests/kwin/TRE-REQ-012.md`, with `repro_cross_window_redraw.py` and `probe_hide.py`).
- `Attach_To` on a Panel (M3b): `Attach_To: <Name>`, `Attach: LEFT | RIGHT | TOP | BOTTOM`, `Gap` (pixels) and `Alignment: START | CENTER | END` (default `CENTER`) place a Panel against a Bar, another Panel (a chain) or a module used in a Bar (`Clock { Name: Clock_One }`). The module's rectangle is where tre laid out its first root block; the Panel meets the Bar's edge, not the module's, so it never covers the Bar, and it slides along the module. A target has one attached Panel; an unknown name, another Monitor, itself, a circle and `Anchor`/`Inset` beside `Attach_To` are errors at load. An attached Panel opens only while its target is open and hides with it. A body that would leave the output is moved back onto it, with a warning. A Panel on a module is placed again when it is shown, after the Bar is laid out and after a reload.
- A Panel now has `exclusive_zone` -1: with 0 the compositor measures its margins from the area the Bars leave free, so an `Inset` was shifted by a Bar's thickness. `Inset` is now from the output's edges, as Panel.md says.
- Stylesheet state selectors (M3b, D39): `Rule { Selector: "Button:hovered" }` and `":pressed"`, after a block word, `.class`, `#name` or a module name, give a block a look while the pointer is over it or a button is down on it. A state rule has the weight of its base selector (name over class over module over type, the later rule wins a tie) and is not held back by the block's own style: it is the look while the state holds. `$token` values in a state rule resolve like those in the base style. The binder listens to `pointer_enter`, `pointer_leave`, `pointer_down`, `pointer_up` and `pointer_cancel` on a block that has a state style, never stops the event (a click still reaches `On_Click` and the blocks around), applies the state's properties with the same conversion as the base, remembers the values they replace and puts them back exactly; pressed shows over hovered, and a leave ends both. A reload keeps a block in the state the pointer has it in with the new look. A `Text` takes no pointer event in tre, so a state rule that reaches one is a load-time warning (`state-never-applies`; put the rule on the box around the text). `:focused`, `:disabled` and `::part` are still read and skipped with a warning that says why: no block can take focus, none has an `Enabled` key and none has named parts yet. An unknown state name is an error naming the four states.
- Popup (M3b, B4): `Popup { Name, Attach, Alignment, Gap, Width, Height, Max_Width, Max_Height, Adjust, Focus, Style, Children }` as a Monitor child. A module opens one beside the use whose `@action` runs with `self.ctx.popup("Menu")` (the shell supplies the calling use; `ctx.popup(name, data=None, use=...)` outside an action takes `use`); calling the open Popup closes it, and opening another closes the first. `self.ctx.close_popup(name=None)` closes it. The built-in action `On_Click: Close` (no `Target`) closes the Popup that holds the block. A Popup is built when it opens: the content is measured in a headless window (`Width: AUTO`, `Height: AUTO`, clamped to `Max_Width` 300 and `Max_Height` 400; taller content scrolls), a tre `PopupWindow` of that size is placed beside the caller's rectangle (the use's first root block) by the spec's `Attach`/`Alignment` table, `Gap` is the distance from the anchor to the visible body whatever the shadow margin, and the content is bound into it. The shell chooses the side itself: under a bottom Bar a Popup opens upward with no setting. It does not leave that to the compositor's `flip_y` because sway and wlroots flip the anchor and the gravity but not the offset, so a gap and a margin that the offset puts right on one side land wrong on the other (measured: a 6 px `Gap` became 6 px of overlap); `Adjust` (default `[FLIP_Y, SLIDE_X]`) is still passed on. `Focus` (default true) is tre's grab: an outside click or Escape closes it, a click on one of the shell's own surfaces closes it (and is not a call to open it again), and a Popup dismissed within 150 ms of opening is logged as a probable denied grab. Not built: `Attach_To` and `Animation` on a Popup, percentages for `Width` and `Height`, submenus, `caller.data` in expressions (`data` is accepted and warned about), and `Call`.
- Tooltips (M3b, B5): `Tooltip: true` on a Popup (no focus, `Open_On_Enter`, `Close_On_Exit`; `Enter_Delay` 500 ms, `Exit_Delay` 200 ms, each key overridable) and, on a block or a module use, `Tooltip: <Popup Name>` or an inline `Tooltip { Children { ... } }`. The pointer must stay on the block for `Enter_Delay`; leaving it, or leaving the tooltip, closes the tooltip after `Exit_Delay`, and crossing from the block into the tooltip keeps it open. A tooltip never opens while a focused Popup is open. An inline tooltip is expanded in the scope of the use that holds it, so `{{ tooltip }}` in it reads that use's values. A `Text` takes no pointer events, so the `Tooltip` goes on the box around it. `Tooltip: Name.tdl` (a Popup in a file) is not built. A `Text` in a Popup with `AUTO` size needs `Height: AUTO` (tre lays out a text with no height at 0).
- Clock: `locale` (for example `de_DE`) names the month and day names, through the C library's `LC_TIME` set around each format and put back at once; a locale the system lacks (`locale -a`) is warned about once and the default names are used. `tooltip_format` (default `%A, %d %B %Y`) is the text of the tooltip the shipped layout opens on the clock (`{{ tooltip }}`); the Clock sends it with the time.
- A Panel's `Animation { Type: SLIDE | FADE | NONE, Duration }` (M3b): `FADE` runs the surface's opacity, `SLIDE` also moves its margin 24 px toward the edge it grows from (its target, or its anchored edge) so it never covers a neighbour; tre runs both in the engine. A Panel that is hidden while it leaves turns round from where it is; a leaving Panel takes no pointer at once; with the desktop's reduced-motion setting nothing moves. A Panel that does not name an `Animation` does not animate.
- A Panel's own events (M3b): `On_Open` and `On_Close` run when the request is made, `On_Visible` and `On_Hidden` when it has happened (after the animation), `On_Toggle` on a Toggle, `On_Anim_Start` and `On_Anim_End`. A shell file's handlers are the shell's actions (`Show`, `Hide`, `Toggle` with a `Target`); a handler loop is stopped after eight turns and logged.
- `Movable: true` on a Panel (M3b): the whole body is a drag handle (tre moves the margins of the anchored edges, clamped to the output, with no Python in the loop); when the button goes up the position is saved in `registry.json` as an `Inset` and used at the next start. A floating Movable Panel is anchored top and left and starts centred. A saved position is kept on the output. `Movable` with `Attach_To` is an error.
- A Panel attached to a module follows it: tre's `layout` event on the module's root block places the Panel again when the module is laid out or changes size.
- A Popup draws no shadow for now (KWin check, 2026-11-06): its transparent shadow margin made KWin place a popup about 30 px from the screen edge and off the caller's edge, and took clicks, because tre cannot yet say which part of a popup is its body (TRE-REQ-007). An `Elevation` or `Shadows` on a Popup is ignored with one warning. An Escape key handler now closes a focused Popup, since tre's grab did not on KWin.

- Monitor hot-plug (M3c, C4): the shell listens to tre's `output_added`, `output_removed` and `output_updated`. Each one plans the shell again for the new list of outputs (the same monitor matcher as at start, so an output another `Monitor` took stays taken) and compares it with what is running by key and output: a surface of another monitor is not touched; one on a removed output (Bars, Panels, a Popup or tooltip open on them, their timers) is closed and dropped; one on a new output is opened as at start (a Panel's `Visible` start state, a Movable Panel's saved position clamped to the output); one whose output changed size or scale gets its geometry set live with no new window, and a Popup open on it closes. The modules are brought to the new set of uses by the reload path (`use_removed` and `use_added`, a module with no use left is stopped and started again when one returns). `Index` is evaluated again on every change, so a `Monitor { Index: 1 }` follows whichever screen is second. A `Monitor { Index: default }` now always carries the output in its surfaces' paths (`Main@HDMI-A-1`), so a second screen does not rename, and recreate, the first one's; a UID registered for the old path form is registered again. `tests/kwin/prepare_m3c_hotplug.py` writes the KWin checklist setup.

- `Frame` (M3c, C1 and C2): a `Frame { }` block in a `Monitor` (one per Monitor) draws a ring around the output and reserves its sides. One painter `LayerWindow` per output (`top` layer, all four anchors, `exclusive_zone` -1, `input_region="auto"`) draws three `path` nodes with `hit_shape="painted"` (outer border band, fill band, inner border band; each an outer contour and an inner one wound the other way, so the opening is a hole that takes no clicks); one 1 px reserver per side with a thickness has that side's total (thickness, both borders and margin) as `exclusive_zone` and takes no input. Keys: `Thickness` and `Margin` (a number, four sides or named sides), `Corner_Radius` (outer, default 0) and `Inner_Radius` (one number or four corners), `Inner_Border` and `Outer_Border { Width, Color }`, `Style { Background, Opacity, Border { Width, Color } }`, `Visible`, `Layer: TOP`. A radius the ring cannot hold is reduced with a warning naming the key; a side of 0 is open (no band, border, margin or reserver). Reload sets the zones, redraws the ring and adds or closes a reserver without making the painter again; `set_look` re-reads the tokens; `Show`, `Hide` and `Toggle` with `Target: <Frame name>` close and reopen all of a Frame's windows (its zones are released and restored). `Edges`, `Children`, `Border_Tile`, `Meld`, gradients, shadows and a Panel `Attach_To` a Frame are load errors (not built). `tests/kwin/measure_frame.py` and `tests/kwin/prepare_m3c_frame.py` measure the Frame's cost and write the KWin checklist.

- Frame strips and melded Panels (M3c, C3): `Edges { Left | Top | Right | Bottom { Thickness, Padding, Children { ... } } }` and a Frame-level `Padding` (the space between a strip's children and its sides; an edge's own wins, an edge's `Thickness` replaces the Frame's for its side, both inside the side's reserved total). A strip is hosted in the Frame's painter (Option A): a box placed in the side's band (top and bottom strips own the corner squares and run the full width; left and right strips run between them and lay their children out vertically; text is not rotated). Strip content is bound like a Bar's tree and is a `Surface` whose window is the painter: module uses in it start with the shell's other uses and get live values, hot reload and hot-plug rebuild it by the keyed diff (the painter and the strip nodes are kept), a new look re-resolves its tokens, and Popups and tooltips open beside its blocks. `Panel { Meld: true, Attach_To: <Frame>, Attach, Alignment, Depth, Length, Style { Corner_Radius } }` (`Depth` is the extent away from the Frame's edge, `Length` the extent along it; `Width` and `Height` on a melded Panel, and `Depth` or `Length` on any other Panel, are errors) is drawn in the same surface: the ring and every melded body are one `path` contour with a fillet at each join that uses the Frame's `Inner_Radius` (by quadrant), the body's own two corners take its `Corner_Radius`, the inner border follows the contour, and the reserved zones do not change. A body flush with a corner replaces that corner of the opening; one larger than the opening is clamped; one that overlaps an earlier one, or sits on a side with no thickness, is not drawn (a warning). `Show`, `Hide` and `Toggle` with `Target: <Panel>` take the body out of the contour and back (no animation); `Visible: false` starts it hidden. A `Margin` on a melded Panel stops the meld (an error); `Hide_After`, `Movable`, `Keyboard`, `Input_Region`, `Animation` and `On_*` events on one, a Panel attached to a Frame without `Meld`, a melded Bar, strip expand, contract and peek stay load errors (not built). The painter's keyboard is `on_demand` when a hosted tree holds a text input and `none` otherwise (v1 has no text-input block, so it is always `none`). `tests/kwin/measure_frame.py --melds=N` measures the one-contour path; `tests/kwin/prepare_m3c_strips.py` writes the KWin check.

- Melded Panel animation, events and `Hide_After`; `Keyboard` on the Frame (M3c): a melded Panel takes `Animation { Type: SLIDE | FADE | NONE, Duration }`, `Hide_After` and the Panel's events with the same semantics as a window Panel (`SurfaceManager._fire`, the generation guard, a timer of the painter window). SLIDE: while it animates, the ring nodes are drawn without the body (at alpha 1, so they keep the ring's click shape) and an `svg` node draws the ring with the body in it: the document holds the contour at depth 0 and at full depth with the same commands (lines and cubic Béziers, a degenerate cubic where a fillet has radius 0, every coordinate linear in the depth), an `<animate attributeName="d">` between them is sampled by tre's own clock (`animate("svg_time", ...)`, eased in the engine, no Python per frame), so the body grows out of the band edge with its joins growing with it, and its content translates on the same clock; when it ends the ring nodes take the body back and the svg is hidden (the two renderings are pixel-identical at scale 1, 1.25 and 1.5, tested). FADE draws the ring without the body and the ring with it in the svg, faded in or out. The svg takes no input (`hit_testable=False`); the ring and strips are drawn above/below it by `z_index` (ring, morph svg, strip and body content), so a strip's blocks are never covered by a body that animates beneath them. A show during a hide (and the reverse) turns round from the current value; `Show`, `Hide` and `Toggle` are idempotent; reduced motion and `Type: NONE` are instant; the sliding layer is `hit_testable=False`, so the part that is out takes no click until it has arrived (the Panel's box and its content do). Animating the path's `data` is not used: tre resamples both contours by length into polylines of 96 points a subpath (corners chamfer at once, the notch smears; `tests/kwin/repro_path_morph_resample.py`). The join spikes are `tests/kwin/spike_join_{a_svg_morph,b_pieces_morph,c_scaled_pieces}.py`. `Frame { Keyboard: NONE | ON_DEMAND }` (default `NONE`, `EXCLUSIVE` is an error: it would take every key of the desktop) sets the painter's keyboard mode, live on reload with the same painter window, together with the rule that a strip holding a text input also asks for `on_demand`; the keys the painter receives are logged at DEBUG. `Movable`, `Keyboard` and `Input_Region` on a melded Panel stay load errors.

- Smoother joins and corners, and demo fixes (M3c, KWin review): the ring's fill and an opaque inner or outer border now overlap (the fill runs 1 px under the border) so the two anti-aliased edges that used to meet on one line no longer let the desktop through as a hairline along the curves (seam pixels were about 75 % opaque, now opaque; a translucent border or a translucent Frame keeps the old abutting edges); a ring with a melded body is written as cubic Béziers (kappa) instead of arcs, with a test that a fillet's midpoint lies on the arc and not on the chord. `tests/kwin/prepare_m3c_hotplug.py`'s check script ignores the shell's own `closed (stopped)` at exit and now fails a run with no unplug; the Menu_Button demo and the Dock centre their text with `Align_Items`/`Justify_Content: CENTER` and `Width`/`Height: AUTO` on the Text.
